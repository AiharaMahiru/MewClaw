# SPEC 标准

本文件定义 dsh-lark 仓库中 **SPEC（规格说明）文件的唯一格式与质量门槛**。`docs/specs/` 下每个包、每个能力缝、每个部署组合都有一份 SPEC；没有 SPEC 的代码不得开始实施。

SPEC 是**契约，不是散文**：它必须精确到"照它实现、照它测试、照它评审"三个动作都不需要再猜。

## 1. SPEC 生命周状态

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `draft` | 首次成文 | 作者完成自检（§4 清单全过） | 评审通过 |
| `review` | 评审中 | 进入评审队列 | 评审意见清零 |
| `accepted` | 实施基线 | 评审通过 + 关联 ADR 已 accepted | 首个实现 PR 合并 |
| `implementing` | 实施中 | 有代码落地 | 验收门禁全绿 |
| `done` | 验收通过 | §5 验收证据齐备 | （归档到 done 状态，随包演进时回到 review） |

状态写在 SPEC 元数据表；状态机流转记录在 `docs/specs/README.md` 索引。

## 2. 文件格式

```markdown
# <包名 / 能力名> SPEC

| 元数据 | 值 |
| --- | --- |
| 包 | `dsh-lark-xxx` |
| 位置 | `packages/lark/xxx` |
| 角色 | Definition / Provider / Consumer / Plugin / Bundle / App |
| 里程碑 | M1 |
| 状态 | draft |
| 关联 ADR | ADR-4, ADR-7 |
| 依赖能力 | `ctx.lark`、`ctx.agents`、`ctx.session` |
| 提供能力 | `ctx.xxx`（Definition 时） |

## 1 目的与边界
## 2 服务契约
## 3 配置契约
## 4 事件契约
## 5 模型可见面
## 6 行为契约
## 7 安全与信任
## 8 测试契约
## 9 迁移映射
## 10 开放问题
```

不适用的小节写 `无` 并给出一句理由，不允许直接省略。

## 3. 各节质量要求

### 1 目的与边界

- 一段话说清这个包**为什么存在**、解决什么；
- **非目标**逐条列出（它明确不做什么、不拥有什么）——边界写死才能防止实现蔓延。

### 2 服务契约（Definition / Provider 时必写）

- 服务键（`ctx.xxx`）、每个方法的完整签名（参数类型 + 返回类型）、JSDoc 级语义：前置条件、后置条件、失败方式；
- 错误分类学：每个方法列全可抛/可返回的错误类型（typed error），注明"哪些是调用方 bug、哪些是环境故障、哪些是用户可见失败"；
- 生命周期：何时创建、何时销毁、并发语义（共享实例？per-scope 实例？）；
- 仅声明**稳定面**；实现细节不写。

### 3 配置契约

- 完整 `Config` 接口，逐字段：语义、默认值、默认值在哪一步显式 resolve、校验规则（range/格式）、变更影响；
- 密钥只能是**凭证引用**（env 变量名 / credentials 文档键），SPEC 中永远不出现密钥值、不出现"读 .env"；
- 违反"无硬编码 tunable"的字段一律拒绝（协议常量、外部规格、安全不变量除外，需注明理由）。

### 4 事件契约

- **发布**哪些事件、**消费**哪些事件，各给完整 payload 字段表（含 `@mode` 语义、是否 `ignorable`）；
- 涉及 session 事件时写明声明合并目标（`SessionEventMap` 新增成员）与字段类型；scoped 键缺省要标注 `@dshScopeScan unsupported`；
- 事件顺序、至少一次 / 至多一次语义、消费方幂等要求。

### 5 模型可见面

- 注册的每个工具：名字、一句话描述、参数 schema（根必须 `type: "object"`）、呈现模式（generic/terminal/diff/locations）、副作用声明、审批类别；
- 注入的提示词段：内容骨架、优先级、来源；
- **模型可见 ⟺ 落盘**映射表：每个可见输入/输出对应哪个 session 事件承载。

### 6 行为契约

- 不变量清单（断言式，可被测试直接检验）；
- 并发语义：队列、串行/并行、同一 owner 上限；
- **失败模式表**：每个可失败路径一行——触发条件 → 观测结果 → 恢复方式（不允许任何"静默跳过"，静默降级必须显式写名并给理由）。

### 7 安全与信任

- 信任边界（哪一侧是不可信输入）；
- 授权检查清单：在哪一步、验什么、来自哪里的值**不能**作为证据；
- fail-closed 场景逐条列出。

### 8 测试契约

- 按行为列测试要求，标注级别：`unit` / `security` / `e2e` / `snapshot`；
- 每个安全不变量至少一条拒绝用例；
- 需要真实飞书/真实 API 的用例单独标注，并给出无密钥时的跳过策略。

### 9 迁移映射

- 来源表：lark-claw 文件 → 处置（`复用` / `重写` / `删除` / `平移`）；
- 行为变化逐条显式记录（哪怕微小）。

### 10 开放问题

- 编号列出待决问题；每个问题标注阻塞哪个里程碑、需要谁拍板；
- 已决问题从本节移出，结论写回对应小节，不留历史叙述。

### 交叉要求（所有 SPEC 共同遵守）

- **代码契约**：实现须精简、可读，配完善中文注释（标识符与类型名用英文，注释与文档用中文）；SPEC 的接口注释即实现的注释基准；
- **轻量预算**：SPEC 必须声明新增依赖及必要性（对照 dsh 已提供能力）；重量级依赖须写明"默认关闭 / 可选挂载"的降级路径；
- **密钥纪律**：本地开发密钥源是自 lark-claw 复制的 `.env`（git-ignored，用户已授权直接使用其中的 key）；SPEC 与配置只出现凭证引用名，永不出现值。

## 4. 作者自检清单（提交 draft 前逐项打勾）

- [ ] 每个方法签名可编译（类型真实存在，不写伪类型）
- [ ] 每个配置字段有默认值与校验
- [ ] 每个事件的 payload 字段表完整
- [ ] 每个模型可见输入有落盘映射
- [ ] 失败模式表覆盖所有网络 / 异步 / 持久化路径
- [ ] 安全不变量有对应拒绝用例
- [ ] 迁移映射覆盖所有来源文件
- [ ] 开放问题全部编号
- [ ] 与蓝图 ADR 无冲突（冲突先改 ADR 或显式标注偏差）
- [ ] 依赖预算已声明（新增依赖及必要性；重量级依赖的降级路径）
- [ ] 密钥只以凭证引用出现；`.env` 仅作本地开发密钥源

## 5. 验收证据

`done` 状态要求 `docs/evidence/` 下存在对应证据：测试结果摘录、快照、烟雾日志。证据是**观测结果**，不是自述。
